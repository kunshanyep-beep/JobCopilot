# JobCopilot · AI 求职助手

面向 BOSS 直聘的 Chrome / Edge 扩展，把岗位收集、薪资过滤、AI 匹配、人工审核和逐岗沟通串成一条可控制的工作流。

## 本版改进

实际使用中，页面上还有岗位，收集却可能提前结束；设置了薪资条件，低薪岗位仍可能进入列表；一次 AI 请求挂起，也可能让整个侧栏停在“筛选中”。本分支围绕这些具体问题完成了以下改进。

| 方向 | 解决的问题 | 本版实现 |
| --- | --- | --- |
| 校招与实习 | 普通职位列表和校园页结构不同，筛选也需考虑应届生经历 | 支持应届生／校招、在校生、经验不限；适配校园卡片与“查看更多”；AI 提示词纳入课程、项目和实习经历 |
| 持续收集 | 重复岗位、慢加载和单入口耗尽导致收集过早结束 | 识别滚动容器、等待异步加载、跟随分页；组合关键词与城市；结果不足时扩展搜索入口 |
| 进度与去重 | 再次收集总从相同入口开始，或重复处理已投岗位 | 保存搜索入口及可识别的分页位置；区分收集历史与已投记录，支持分别重置进度和清理收集历史 |
| 薪资过滤 | 私有字体数字被误判为未知薪资，绕过最低薪资要求 | 解码已知字体数字；支持月薪／日薪／年薪区间；在收集、审核和投递前复用同一套规则 |
| 聊天兼容 | “继续沟通”弹窗、页内聊天和独立聊天页行为不同 | 按页面状态等待可用编辑器；校验发送结果；保留已有草稿，图片未确认时单独提示 |
| 异常恢复 | AI 请求挂起、后台重启或脚本注入失败使界面卡住 | 请求超时与取消、筛选结果逐项保存、后台恢复、权限预检查，以及侧栏旧状态响应保护 |

### 三个代表性场景

- **116 个结果中，92 个重复、24 个不符合薪资**：在回归场景中，当前入口没有新岗位时会继续下一搜索入口，进度可跨次保存；搜索仍受每轮预算和网站可用结果限制。
- **设置 15K 下限，却出现 3–4K 岗位**：先将已知私有字体字符转换为数字，再做薪资判断；无法解析的格式不会借“保留面议”绕过筛选。
- **AI 请求一直没有响应**：25 秒超时覆盖响应头和响应体等待，异常项保留原因并进入人工审核；停止可取消挂起请求，后台重启可恢复已保存的部分结果。

## 工作流程

```mermaid
flowchart LR
    A[配置简历与搜索条件] --> B[收集岗位]
    B --> C[去重与薪资过滤]
    C --> D[AI 匹配与理由]
    D --> E[人工勾选审核]
    E --> F[核验条件并读取 JD]
    F --> G[生成招呼语并逐岗沟通]
    G --> H[核对发送结果并记录]
```

AI 初筛使用简历文字与岗位摘要，投递阶段结合岗位 JD 生成招呼语。AI 未推荐或筛选异常的岗位仍可人工选择；投递由用户确认所选岗位后启动。简历图片可选，未配置时只发送文字。

## 技术实现

技术栈：**Manifest V3、原生 JavaScript、Chrome Extension API、DeepSeek API、Node.js Test Runner、jsdom**。扩展直接加载运行，无需前端构建。

### 1. 将收集过程拆成可恢复的搜索计划

后台组合关键词、城市和人群条件，每轮最多访问 12 个搜索入口；列表脚本负责滚动、加载检测与分页信息提取，后台负责导航和进度保存。只有进入审核后的批次才写入收集历史，避免中途停止导致尚未审核的岗位被当作已处理。

按关键词搜索使用独立工作标签；当前页模式沿用页面已有筛选条件，会滚动和翻页。扩展搜索优先原关键词，仅在选择全国时补充城市入口，指定城市时不扩大城市范围。

源码：[后台编排](JobCopilot%20%C2%B7%20AI/src/background.js) · [页面收集](JobCopilot%20%C2%B7%20AI/src/content-search.js)

### 2. 让薪资规则在三个阶段保持一致

将字体归一化、金额解析、配置校验和区间判断集中在 `salary.js`，供页面收集、侧栏审核和后台投递共用。薪资不符的岗位在 AI 调用前被排除；投递前再次读取已保存条件，防止旧审核列表绕过新规则。

区间采用**有交集即保留**的规则：期望 15–25K 时，10–20K 与 25–30K 都会保留。月薪、日薪、年薪分别比较，不推算工作天数或额外薪数；面议与解析异常分别处理。

源码：[薪资规则](JobCopilot%20%C2%B7%20AI/src/salary.js) · [侧栏审核](JobCopilot%20%C2%B7%20AI/src/sidepanel.js)

### 3. 为异步流程定义退出和恢复方式

AI 初筛以每批 3 个岗位并发执行，通过 `AbortController` 和超时控制结束挂起请求；每个已完成结果串行写入 `chrome.storage.local`。后台重启后恢复已完成项并提示中断，由用户审核或重新收集。页面脚本注入设置 10 秒超时，启动前检查网站权限。

聊天适配层统一识别确认弹窗、页内聊天和独立聊天页。文字发送同时检查输入清空与新增对应消息，图片单独核对；文字已确认发送后记录去重，避免因图片待核对而重复发送文字。

源码：[请求与恢复](JobCopilot%20%C2%B7%20AI/src/background.js) · [聊天状态识别](JobCopilot%20%C2%B7%20AI/src/chat-ui.js) · [发送确认](JobCopilot%20%C2%B7%20AI/src/content-chat.js)

## 快速开始

### 安装扩展

```bash
git clone https://github.com/kunshanyep-beep/JobCopilot.git
```

1. 打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`。
2. 开启开发者模式，点击“加载解压缩的扩展”。
3. 选择仓库内的 **`JobCopilot · AI` 文件夹**，其中包含 `manifest.json`。
4. 登录 BOSS 直聘，点击扩展图标打开侧栏。

使用扩展无需安装 npm 依赖；npm 仅用于本地测试。更新代码后，在扩展管理页重新加载扩展，再刷新要操作的 BOSS 页面并重开侧栏。

### 配置并开始

| 配置项 | 用途 |
| --- | --- |
| DeepSeek API Key | 调用岗位匹配与招呼语生成服务 |
| 简历文字 | 提供 AI 匹配与生成内容的依据，必填 |
| 简历图片 | 可选，投递时发送给招聘方 |
| 收集来源 | 按关键词搜索，或从当前 BOSS 列表／校园页收集 |
| 人群、关键词、城市 | 关键词模式下使用，关键词与城市支持逗号分隔 |
| 薪资与收集数量 | 控制候选范围；数量指薪资过滤、去重后的 AI 初筛前岗位数 |
| 自动扩展与未见岗位 | 控制结果不足时的搜索范围，以及是否跳过收集历史 |

例如，选择“应届生／校招”，填写 `前端开发，Web开发` 和 `北京，上海`，设置收集数量为 20。点击“开始收集 + AI 筛选”，查看理由并勾选岗位，再点击“投递选中”。

“下次从首个搜索入口开始”只重置搜索进度；“清空收集历史”同时清理收集历史和搜索进度，两者都保留已投记录。**“重置”会清空已投记录**，可能使同一岗位再次进入投递范围。

## 适用范围与数据流

- 当前适配 BOSS 直聘；公司独立校招官网、网申表单不在支持范围内。遇到登录或验证提示会停止搜索，等待人工处理。
- 搜索进度可恢复到已保存入口和可识别的分页地址，不保证恢复已关闭页面的无限滚动位置，也不保证凑满目标岗位数。
- 配置、简历和运行记录保存在浏览器扩展本地存储中；AI 调用会将简历文字与岗位信息发送至 DeepSeek，确认投递后会向招聘方发送相关文字及已配置的简历图片。
- 页面结构或字体编码变化可能需要更新适配逻辑。使用时应遵守平台规则、核对生成内容，并合理控制沟通频率。
